# **요구사항 명세서 (SRS)**
---

## **1. 시스템 개요**

**목적:**  
온라인 쇼핑몰 상품 링크를 입력받아 가격, 리뷰, 판매자 정보를 분석하고,  
사기 및 조작 가능성을 점수화(BRS)하여 사용자가 안전한 구매 결정을 내릴 수 있도록 돕는다.

**핵심 기술 스택:**

- **Backend:** Node.js + Express
    
- **Frontend:** React SPA
    
- **DB:** DynamoDB (로컬 or AWS)
    
- **AI:** AWS Bedrock Claude Sonnet 4.0
    
- **Infra:** AWS Lightsail + Nginx + PM2
    
- **Crawler:** Cheerio 기반 HTML 파서

### **MAD (Median Absolute Deviation)**

- **역할:** 상품 가격이 **정상 시세에서 얼마나 벗어났는지**를 통계적으로 판단
    
- **방식:**
    
    1. 여러 상품의 **가격 중앙값** 계산
        
    2. 각 가격이 중앙값에서 얼마나 떨어졌는지(절대편차) 측정
        
    3. 편차가 **너무 크면 이상치(비정상 가격)**로 판단
        
- **결과:** “가격 위험 점수” 생성 (BRS 구성요소 중 하나)
    

---

### **BRS (Blackcow Risk Score)**

- **역할:** 상품의 **종합 사기 위험도 점수 (0~100점)**
    
- **구성 요소:**
    
    - 가격 이상치 점수 (MAD 결과)
        
    - 리뷰 패턴 및 감정 조작
        
    - 판매자 신뢰도
        
    - 마케팅 키워드 감지
        
- **계산:** 각 요소에 가중치를 부여해 합산  
    → 점수에 따라 “낮음 / 중간 / 높음” 분류

## **3. 상세 요구사항**

### **요구사항 4: 리뷰 패턴 분석 및 감정 어뷰징 탐지**

**사용자 스토리:**

> 리뷰가 조작되었는지 또는 비정상적으로 몰려 있는지 알고 싶다.

**인수 기준:**

1. 최대 30개의 최근 리뷰를 수집한다.
    
2. 3일 이내 작성 리뷰가 50% 이상 → **리뷰 폭증 패턴** 표시
    
3. 동일 문구(10자 이상)가 30% 이상 → **반복 패턴** 표시
    
4. Claude Sonnet 4.0으로 각 리뷰 감정 분류 (긍정/중립/부정)
    
5. 긍정 리뷰가 90% 이상 → **감정 다양성 부족** 표시
    
6. “정품”, “공식”, “최저가”, “가성비” 등 **마케팅 키워드 다수 포함 시 어뷰징 의심**
    
7. 감정 이상 + 어뷰징 동시 탐지 시 BRS에 **+10점 가중치**
    

---

### **요구사항 5: BRS 계산 및 분류**

**사용자 스토리:**

> 종합 위험 점수와 그 근거를 받고 싶다.

**인수 기준:**

1. 모든 위험 요소를 합산해 BRS(0~100) 계산
    
2. 점수 구간별 분류:
    
    - 0~30: 낮음
        
    - 31~60: 중간
        
    - 61+: 높음
        
3. 10점 이상 기여한 요소에 근거 코드 생성
    
4. 요청 후 **10초 이내**에 분석 결과 반환
    

---

### **요구사항 6: 대안 상품 추천**

**사용자 스토리:**

> 사기 의심 상품의 대체 상품을 보고 싶다.

**인수 기준:**

1. BRS > 40일 때 동일 상품명으로 대안 검색
    
2. 대안 상품마다 BRS 명시
    
3. 가격 오름차순 정렬
    
4. 사용자가 각 대안의 BRS를 직접 비교 가능
    

---

### **요구사항 7: 오류 처리**

**사용자 스토리:**

> 시스템이 오류 발생 시도 중단 없이 결과를 제공하길 원한다.

**인수 기준:**

1. 크롤링 실패 3회 시 **부분 분석 결과 반환**
    
2. 외부 호출 5초 이상 타임아웃 → **해당 단계 건너뛰기**
    
3. AI 호출 실패 시 **규칙 기반 폴백 로직 적용**
    
4. 모든 오류 **Winston 로깅**
    

---

### **요구사항 8: 성능 및 확장성**

**사용자 스토리:**

> 시스템이 빠르고 효율적으로 동작하길 원한다.

**인수 기준:**

1. 상품 데이터 **DynamoDB 캐싱 (6시간 TTL)**
    
2. AI 분석 결과 캐싱으로 중복 호출 방지
    
3. 사용자당 **분당 10개 요청 제한**
    
4. HTML 파싱은 **Cheerio 사용**
    

---

### **요구사항 9: 배포 및 운영**

**사용자 스토리:**

> 저비용 단일 서버에서 운영 가능해야 한다.

**인수 기준:**

1. AWS Lightsail 단일 서버에 배포
    
2. Nginx 리버스 프록시 구성
    
3. PM2로 Node.js 프로세스 관리
    
4. DynamoDB Local 사용 가능
    

---

### **요구사항 10: 기본 사용자 인터페이스**

**사용자 스토리:**

> 간단한 웹 인터페이스에서 결과를 확인하고 싶다.

**인수 기준:**

1. `POST /api/analyze` 엔드포인트 제공
    
2. BRS, 위험 수준, 근거 코드, 추천 포함 JSON 반환
    
3. React 기반 SPA UI
    
4. 결과 카드형 시각화
